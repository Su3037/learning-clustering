# 04 · Site and design system

The site is plain static files: HTML generated by small Node scripts, one stylesheet, ES modules, bundled
fonts, no framework, no CDN, no build-time bundler. Visitors install nothing. Reference: `site/assets/`,
`scripts/build-site.mjs`.

## 1. Look and feel

Modelled on the author's Label Propagation site, which the author called "very elegant":

- **Warm paper** reading areas, **light serif** display type, **monospace eyebrows** (`MODULE 05 / LABEL
  PROPAGATION`), **hairline rules** instead of boxes, generous whitespace, numbered section heads
  (`01 / 目标与问题`), a sticky table of contents for the lesson.
- One deep-teal accent; gold for emphasis; dark **cinema bands** for films and labs.
- Rejected earlier: bold Noto Sans headings everywhere ("heavy and crowded"), pill tags, boxes around everything.

### Type

| Role | Chinese pages | English pages |
| --- | --- | --- |
| Display (h1–h3) | Noto Serif SC, weight 400 | Newsreader, weight 400 |
| Text | Noto Sans SC, 16.5 px / 1.75 | Noto Sans, 17 px / 1.65 |
| Labels, code, numbers | JetBrains Mono | JetBrains Mono |

All fonts are OFL, self-hosted as WOFF2 and **subset to the characters the site uses**
(`scripts/build-fonts.py`, fontTools). Re-run the subset whenever text changes, or new characters fall back to
system fonts (a test checks coverage). Keep Chinese curly quotes full-width (route U+2018–201F to the Han face).

## 2. Languages

- Chinese at the original URLs, English mirrored under `/en/`. `<html lang>` drives everything:
  `L('中文', 'English')` in scripts, `T(zh, en)` in the generator.
- Sources: `module.json` / `module.en.json`, `lesson.md` / `lesson.en.md`, `slides.json` / `slides.en.json`,
  Python packs `python/<id>/` and `python/<id>/en/`. Films render once per language from the same script.
- The 中文 / EN switch keeps the reader on the same page and section; the choice is remembered. Readers whose
  browser is not Chinese get a one-time offer of English.
- English pages contain no leftover Chinese except term pairs in the glossary and proper names.
- Write English as a native technical writer would, not as a literal translation.

## 3. Components

| Component | File | Behaviour |
| --- | --- | --- |
| Shell | `core.js` | header, nav, language switch, reduce-motion and sound toggles, toasts |
| Film player | `media.js` | four film cards, chapters, transcript, VTT, poster, language-matched source |
| Slides viewer | `module-page.js` | slide + transcript below, thumbnails, search, keys, `#slide-<id>` deep links |
| Graph view | `graphview.js` | SVG graph, group colours, cut edges, labels readable on phones |
| Lab | `lab.js` + `modules/<id>/lab.js` | engine stepping, pseudocode line highlight, state panels, export run |
| Challenges | `challenges.js` + `modules/<id>/challenges.js` | inputs, check, two hints, answer, status |
| Code lab | `codelab.js`, `py-worker.js` | CodeMirror 6 editor, Pyodide in a worker, checks, visualiser |
| Progress | `progress.js` | localStorage with schema, export / import, survives storage errors |

### Code lab details
- Pyodide (self-hosted, e.g. 0.28.3, MPL-2.0) loads on first Run (~12 MB, cached). CodeMirror 6 bundled.
- The worker is terminated to stop infinite loops; a new one starts on the next run.
- Checks run the same `check.py` as the download with `--json`; results per named check:
  PASS / FAIL / INCOMPLETE. Unfinished code is INCOMPLETE, never PASS.
- The learner's code is saved per module and language.
- After the checks pass, a visualiser runs the learner's own functions on the example and compares each step
  with the course engine.

## 4. Robustness requirements

- Works under a GitHub Pages project subpath (`/<repo>/`): only relative paths; exact filename case.
- Every relative link and asset resolves (test). No external CDN or font service (test).
- `.nojekyll` at the site root.
- 375 px width: no horizontal page scroll; code blocks and tables scroll inside themselves; lab toolbars wrap;
  40 px tap targets on touch screens; larger graph labels on narrow screens.
- Keyboard: every control reachable; arrows step the lab and slides; visible focus ring.
- `prefers-reduced-motion` and a manual "reduce motion" toggle.
- localStorage may throw: the page still works and says progress is kept only for this visit.
- Missing media shows a clear message, not a broken player.
- 404 page that finds its way back under the project subpath.

## 5. Deploy

GitHub Actions workflow (`.github/workflows/pages.yml`): on push to `main`, a **test** job (Node tests,
cross-check, every Python reference against its checker) gates a **deploy** job that uploads `site/` to
Pages. Settings → Pages → Source: GitHub Actions. After deploy, re-check the live URL (fonts load with 200,
films seek, labs run), not only localhost.
