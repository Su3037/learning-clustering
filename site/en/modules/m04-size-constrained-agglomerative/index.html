What this module solves

Problem statement

Input

A weighted undirected graph, a size s(v) for each node (area or cell count), a capacity C, and a target number of clusters K.

Output

Legal clusters, the cut, the actual number of clusters, capacityCompliant, targetReached, the stop reason; optionally an exhaustive diagnosis.

Objective

Reduce the cut by greedy merging while every cluster’s total size stays ≤ C, and reach K if possible.

Constraints

Hard capacity: no merge may produce a cluster larger than C; K never overrides the capacity; if a single node already exceeds C, the input itself is invalid.

Assumptions

A cluster’s size = the sum of its members’ sizes; legal candidates are filtered first, then chosen by (−affinity, members, members); the exhaustive diagnosis is only for teaching graphs of at most 10 nodes.

Stopping

K is reached, or no legal pair with positive affinity remains (capacity-blocked / no-positive-affinity). Then the lower bound and exhaustive search tell which ending it is.

§ 1The same rule, one more question: does it fit?

The merge rule is exactly Module 03’s: start from singletons, each time merge the pair with the largest total weight between them, compare selection keys field by field, never undo. Only one thing changes:

Filter for legality first, then take the largest. A candidate whose merged cluster would exceed the capacity C cannot be chosen, however high its affinity.

In a real circuit a cluster often stands for a region of the chip, and that region holds only so much cell area. The constraint looks simple, yet it gives greedy merging three different endings. This chapter’s job is to tell them apart.

§ 2Size, capacity and the four report items

size s(v)

单元大小

The area or resources one node takes. In this chapter every node of G01 has size 1; in greedy_trap, A and B have size 2.

capacity C

容量

The upper limit on a cluster’s size: the sizes of all nodes in a cluster add up to at most C.

capacity compliant

合法

Every cluster respects the capacity.

target reached

达到目标

The actual number of clusters is ≤ K.

The four are independent and must be reported separately:

Report itemMeaningWith capacity 2, K = 2
countThe actual number of clusters3
capacityCompliantEvery cluster’s size ≤ Cyes
targetReachedcount ≤ Kno
stopReasonWhy it stoppedcapacity-blocked
K never overrides the capacity

Making one over-capacity merge to reach K makes the result illegal. Better to stop with more clusters and say so honestly. When a single node already exceeds the capacity, no legal grouping exists at all; this course reports that as an input error instead of forcing merges.

§ 3One graph, two capacities

On G01 with K = 2, compare capacity 3 with capacity 2:

1A–B (5), size 2, legalA–B (5), size 2, legal
2AB–C (1+4=5), size 3 ≤ 3, legalAB–C has size 3 > 2, blocked; D–E (5) instead

With capacity 2, the blocked candidate is not a “small” one but exactly the highest-affinity AB–C. The legality filter happens before affinities are compared.

§ 4Impossible, or a dead end?

At capacity 2, G01 stops at 3 clusters. Is that greedy’s fault? First compute a lower bound:

The total size is 5 and each cluster holds at most 2, so at least ⌈5 / 2⌉ = 3 clusters are needed.

No algorithm can split G01 into 2 clusters at capacity 2. Greedy made no mistake here: the target itself is infeasible.

A lower bound can only prove “impossible”, never “possible”. The greedy_trap graph by the original author, GateUltra, shows a different situation:

  • Nodes A and B have size 2, C and D size 1; edges C–D = 10, A–C = 4, B–D = 4; capacity 3, K = 2.
  • Lower bound: total size 6, ⌈6/3⌉ = 2 ≤ K, so the bound allows 2 clusters.
  • Greedy: it first merges C–D (10), the highest affinity, giving CD of size 2; then CD+A and CD+B both have size 4 > 3, and there is no edge between A and B. It stops at 3 clusters.
  • Exhaustive search: AC | BD, two clusters of size 3 each, legal, cut = C–D = 10.

So greedy_trap is “feasible overall, but greedy is stuck”: the first step took the biggest 10, and after that no legal pair of clusters can be assembled. Greedy never backtracks, so it has no way to find that way out.

A counter-intuitive detail

When greedy stops, its cut is 8 (A–C 4 + B–D 4), smaller than the feasible 2-cluster plan (cut 10), because it has one more cluster. A small cut does not mean the target is reached; keep the two apart.

§ 5Legal, but not optimal

The third ending comes from the original author’s suboptimal graph: edges A–B = 10, A–C = 9, B–D = 9, C–D = 1, every node of size 1, capacity 2, K = 2.

  • Greedy: it first merges A–B (10); AB is then full, so only C–D (1) can merge. The result is AB | CD, cut = 9 + 9 = 18.
  • Exhaustive search: AC | BD cuts only A–B (10) and C–D (1), cut = 11.

Both results are legal and both reach K, but greedy is 7 worse than the optimum. The reason is the same as in greedy_trap: the first step took the biggest 10 in sight and left both 9s in the cut.

Node sizes change the ending too

Set A’s size in G01 to 2, with capacity 3 and K = 2: after A–B merges its size is already 3, AB+C becomes 4 and is blocked, so greedy merges D–E instead and then puts C into DE. The result is AB | CDE, cut 5, not the original ABC | DE, cut 3. Counting nodes and counting area can give different answers.

§ 6The pseudocode: merge, report, diagnose

  1. clusters ← singletons; if some s(v) > C: report invalid input
  2. while |clusters| > K:
  3. cands ← cluster pairs with affinity > 0
  4. legal ← {(P, Q) ∈ cands : s(P) + s(Q) ≤ C}
  5. if legal is empty: stop ← capacity-blocked or no-positive-affinity
  6. merge the legal pair with the smallest selection key
  7. report: count, capacityCompliant, targetReached, stop
  8. diagnose: lower bound ⌈Σs / C⌉ and small-graph exhaustive search

How it maps to the Python: lines 1–6 → solve(); line 7 → report(); line 8 → oracle() and classify().

§ 7Practice and limits

In chip design, the capacity constraint means “how much area fits in each region”. Capacity-constrained clustering often serves as a coarsening step: it combines a large number of cells into clusters of controlled size before handing them to partitioning or placement.

  • A lower bound can only prove impossibility; “possible” needs an actual legal grouping, which is as hard as bin packing.
  • This chapter’s exhaustive search only suits 10 nodes or fewer; at real scale you need heuristics or mathematical programming, usually with no guarantee of optimality.
  • Greedy never backtracks. In a dead end, all it can do is report honestly; improving on it needs methods that allow moving back or swapping, which is the subject of Modules 07 and 08.

08 / Common mistakes and limits

Where it goes wrong

Each entry gives the wrong result, the cause, a counterexample and the fix; every number in the counterexamples is recomputed by the tests.

Calling “legal” “done”

Wrong result
At capacity 2, getting AB | C | DE and reporting “clustering succeeded”.
Why
Legal only says no cluster is over capacity; the target is K = 2 and there are 3 clusters.
Counterexample
The same grouping is legal and on target at K = 3, and legal but off target at K = 2.
Fix
Report four items separately: count, capacityCompliant, targetReached, stopReason.

Breaking the capacity to reach K

Wrong result
Squeezing C into AB to get ABC | DE, size 3 > 2.
Why
The capacity is a hard constraint; K is only a target and never overrides it.
Counterexample
5 units of size at capacity 2 need at least ⌈5/2⌉ = 3 clusters: no legal solution with K = 2 exists at all.
Fix
Compute the lower bound first; when it exceeds K, say plainly that it is impossible.

Taking “greedy is stuck” for “impossible”

Wrong result
greedy_trap stops at 3 clusters, so you declare “2 clusters are impossible at capacity 3”.
Why
Stopping only says greedy’s path is blocked; another legal grouping may exist.
Counterexample
greedy_trap: greedy merges C–D (10) first, after which neither A nor B fits; exhaustive search finds AC | BD (sizes 3 and 3), 2 clusters, cut 10.
Fix
Check with exhaustive search (small graphs) or another method before concluding.

Assuming a legal result is optimal

Wrong result
On the suboptimal graph greedy gets AB | CD, cut 18, and you take it as the answer.
Why
Greedy took the largest A–B (10) first and left both 9s in the cut.
Counterexample
The legal AC | BD cuts only A–B 10 and C–D 1: cut 11.
Fix
Say “legal” and “optimal” separately; when you need the optimum, compare against something.

Treating node count as area

Wrong result
Counting every cell as size 1 and ignoring differences in area.
Why
Real cells differ in area; the capacity counts the sum of sizes.
Counterexample
Set A’s size in G01 to 2 with capacity 3: the result changes from ABC | DE (cut 3) to AB | CDE (cut 5).
Fix
State every node’s size explicitly in the input.

Scope and limits

  • The lower bound ⌈total size / C⌉ can only prove “impossible”, never “possible”: bin packing itself is hard.
  • The exhaustive oracle only suits teaching graphs of at most 10 nodes (the number of set partitions grows extremely fast); real sizes need heuristics or mathematical programming.
  • Greedy never backtracks: once in a dead end it can only report it, not find a way out.
  • This module has a single constraint (capacity); real designs also have timing, pin counts and more (Module 09 discusses delay).
