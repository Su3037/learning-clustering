01 / Goals and problem

What this module solves

Start with the problem and what counts as success, then the algorithm. Each goal links to where it is taught.

Recap前面七个模块都在减少 cut。本章换一个目标：信号从输入走到输出的最长延迟。图也换成有方向的组合电路（DAG）。

Learning goals

  1. 说明目标从“最小 cut”变为“最小 PI→PO 最大延迟”，并用四节点链手算：跨簇一次 7，两次 10。目标变了：从 cut 到延迟 · [概念] 目标变了 · [推演] 一条路径的延迟

Problem statement

Input

组合电路 DAG（无环）、每个节点的延迟 δ(v) 与大小 s(v)、簇容量 M、跨簇延迟 D；PI 为没有输入的节点，PO 为输出。

Output

每个节点的标签 l(v)、被选中的簇、物理实例与实例连线、各 PO 的到达时间与最大延迟、复制的节点与总面积。

Objective

最小化从任一 PI 到任一 PO 的最大路径延迟。

Constraints

每个簇的大小之和 ≤ M；簇内连线额外延迟 0，跨簇连线额外延迟 D；每个实例的输入必须完整。

Assumptions

允许复制逻辑节点（这是最优性结论的前提）；本课程教学例 δ = 1、s = 1；平票：l(x)+Δ(x,v) 相等时拓扑序靠后者优先（候选假设）。

Stopping

标记阶段处理完所有非 PI 节点；恢复阶段从 PO 出发，直到所有需要的簇都已生成。输入有环时报错，不做任何近似。

03 / Lesson · from intuition to pseudocode

From an example to pseudocode

§ 1目标变了：从 cut 到延迟

前面七个模块都在减少 cut——跨组连线越少越好。可是在芯片里，很多时候更要紧的是快：信号从输入走到输出，最慢的那条路径决定了电路能跑多快。

把电路分进不同的簇（例如不同的芯片区域或器件），跨簇的连线比簇内的慢得多。于是问题变成：怎样分簇，才能让最长路径的延迟最小？

先看一条最简单的链：P → X → Y → O，每个节点延迟 1，每次跨簇多加 D = 3，每个簇最多放 2 个节点。

分法路径上跨簇次数延迟
{P, X} | {Y, O}1（X→Y）4 + 3 = 7
{P} | {X, Y} | {O}2（P→X、Y→O）4 + 3 + 3 = 10

两种分法都满足容量，延迟却差了 3。延迟只看最长路径跨了几次边界，而不是总共切断了多少条连线。在分叉的电路上，两种分法切断的连线数可以相同，关键路径的跨界次数却不同。

§ 2模型：DAG、延迟、容量

有向无环图

DAG

组合电路：信号沿有向边流动，没有环。本章不使用前面的无向五节点图。

主输入 / 主输出

PI / PO

没有输入的源节点 / 电路的输出。

节点延迟

node delay δ(v)

信号经过节点 v 需要的时间。本章例子 δ = 1。

跨簇延迟

inter-cluster delay D

一条连线的两端在不同簇时额外增加的固定延迟；簇内为 0。它和 Module 06 里的度矩阵 D 无关。

簇容量

capacity M

每个簇的大小上限。本章例子每个节点大小 1、M = 4。

一条路径的延迟 = 路径上所有节点的 δ 之和 + D × 跨簇次数。电路的延迟 = 所有 PI→PO 路径中的最大值。

背景：Lawler、Levitt 与 Turner（1969）研究过单位延迟的模块聚类；Rajaraman 与 Wong 在 DAC 1993 提出、并于 1995 年在 IEEE TCAD 发表了适用于一般节点延迟的算法，证明在允许复制节点的条件下能得到最大延迟最小的聚类。

§ 3复制：一个逻辑节点，多个实例

逻辑节点

logicalId

电路中的一个门或单元（例如 b）。

物理实例

instanceId

逻辑节点放在某个簇里的一份副本，本课程写作“节点@簇根”（例如 b@d）。

复制

replication

同一个逻辑节点在多个簇里各放一份实例。每个实例都要有完整的输入。

为什么要复制？如果一个节点同时供给两个延迟关键的簇，把它放进其中一个，另一个簇就得跨界取信号，多付 D。复制一份，两个簇都能在簇内拿到它。

复制不是免费的，也不能用“节点 → 簇”表示

每个副本都占面积。12 个逻辑节点的候选例子最终有 20 个实例。数据结构上，一个“节点 → 簇”的映射只能给每个节点一个簇；复制后必须分开记录逻辑节点与实例，并检查每个实例的输入完整。本课程引擎的 instances[{instanceId, logicalId, clusterId}] 与实例连线就是为此设计的。

§ 4初始化：最长节点延迟 Δ

候选例子（由原作者 muranfei 影片中的图复原，候选状态）有 12 个节点 a–l：PI 为 a、b、c，PO 为 k、l，15 条有向边。

Δ(x, v)：从 x 到 v 的所有路径中，节点延迟之和的最大值——计 v，不计 x。没有路径时不定义。

例如 b → e → g → i → k 经过 e、g、i、k 四个节点：Δ(b, k) = 4。原作影片 438 秒处给出了完整的 Δ 表，本课程用复原的边表重新计算，与它逐项一致。

PI 的标签就是它自己的延迟：l(a) = l(b) = l(c) = 1。

§ 5标记：l(v) = max(l1, l2)

按拓扑序处理每个非 PI 节点 v：

  1. 对 v 的每个祖先 x，算 l(x) + Δ(x, v)——“如果 x 之前的部分已经尽量快，信号从 x 走到 v 需要多久”。
  2. 按这个值从大到小排序（相等时，本课程假设拓扑序靠后的优先——候选假设）。
  3. 把 v 和排在前面的祖先依次放进候选簇，直到容量 M。
  4. l1 = 簇内 PI 的最大值；l2 = 簇外祖先的最大值 + D。l(v) = max(l1, l2)。

以 i 为例（容量 4）：

祖先 xl(x) + Δ(x, i)在簇内？
g3 + 1 = 4是
e2 + 2 = 4是
c1 + 3 = 4是（PI）
b1 + 3 = 4否
f、d、a3否

l1 = 4（簇内 PI c），l2 = 4 + 3 = 7（簇外最大的是 b）。l(i) = 7。最后 l(k) = l(l) = 8。

两种“标签”

RW 的 l(v) 是一个时间；Module 05 的标签是一个群体记号。两者同名，含义完全不同。

§ 6恢复：从输出倒推簇与实例

标记只给出每个节点的候选簇。真正用到的簇从 PO 倒推：

  1. 从 k、l 开始，取它们的候选簇：k 的簇 {g, i, j, k}，l 的簇 {e, g, j, l}。
  2. 簇外的输入节点（k 的簇需要 d、e、f、h；l 的簇需要 b、c、h）各自成为新的簇根，取它们的候选簇。
  3. 重复直到不再需要新的簇。

候选例子得到 8 个簇、20 个实例；g、j、e、a 各有 2 个实例，b、c 各有 3 个。每个实例的输入都完整（本课程测试检查）。两个输出的到达时间都是 8，等于标签。

和不复制相比：同样容量 4、同样 D = 3，如果每个节点只能在一个簇里，本课程穷举所有合法分组得到的最好最大延迟是 10。复制用 8 个额外的实例换来了 2 个单位的延迟。

§ 7伪代码

  1. 检查输入是 DAG；求拓扑序；计算 Δ(x, v)
  2. for 每个 PI p: l(p) ← δ(p)
  3. for 每个非 PI 节点 v（拓扑序）:
  4. score(x) ← l(x) + Δ(x, v)，对 v 的每个祖先 x
  5. 候选簇 ← v + 按 score 降序的祖先，直到容量 M
  6. l1 ← 簇内 PI 的最大 score；l2 ← 簇外最大 score + D
  7. l(v) ← max(l1, l2)
  8. 从 PO 倒推：取候选簇，簇外输入成为新的簇根
  9. 为每个（簇根, 成员）生成实例，连接实例边

Click any line for its explanation. When you step through the lab, the line being executed lights up.

和 Python 的对应：第 1 行 → topological_order()、longest_node_delays()；第 2–7 行 → rw_label()；第 8–9 行 → rw_reconstruct()；到达时间 → evaluate_instance_delay()。

§ 8适用边界与待确认事项

  • 最优性只在模型内：DAG、节点延迟、簇内 0、跨簇固定 D、容量、允许复制。禁止复制、或者同时要求面积/引脚/功耗最优时，不能沿用这一结论。本课程的测试检查实现的一致性，不证明最优性。
  • 候选数据：12 节点例子由原作影片画面复原；“相等时逆拓扑序优先”是假设。它重现了 8 簇、20 实例、输出 8，但原始边表与平票规则待原作者确认。
  • 课程对应：这份提交编号为 Lesson 9，而教师目录的 Lab 09 是 Multilevel。本模块按提交保留 RW，不替代 Multilevel，对应关系待教师确认。
  • 工程含义：延迟驱动的聚类常用于把电路分到多个芯片或 FPGA 区域时减少跨区延迟；复制换来速度，也带来面积。

08 / Common mistakes and limits

Where it goes wrong

Each entry gives the wrong result, the cause, a counterexample and the fix; every number in the counterexamples is recomputed by the tests.

以为 cut 小就延迟小

Wrong result
选跨簇边最少的分法，认为关键路径最快。
Why
延迟只看最长的那条路径经过了几次边界；跨簇边的总数不直接决定它。
Counterexample
四节点链分成 {P,X} | {Y,O}：1 条跨簇边、延迟 7；分成 {P} | {X,Y} | {O}：2 条跨簇边、延迟 10。在分叉的电路上，跨簇边数相同的两种分法，关键路径的跨界次数可以不同。
Fix
按路径计算延迟：节点延迟之和 + D × 路径上的跨界次数，取所有 PI→PO 路径的最大值。

用“节点 → 簇”的映射表示复制

Wrong result
给每个节点记一个簇号，复制时把同一节点写进两个簇。
Why
一个映射表只能给每个节点一个簇；复制后同一个逻辑节点有多个物理实例，每个实例有自己的输入。
Counterexample
候选图里逻辑节点 b 有 3 个实例：b@b、b@d、b@e。
Fix
逻辑节点与实例分开：instances[{instanceId, logicalId, clusterId}] + 实例连线，并检查每个实例的输入完整。

把复制当成免费的

Wrong result
为了缩短延迟，随意复制节点。
Why
每个副本都占面积；RW 的结论是在允许复制、并满足容量的前提下延迟最优，不是面积最优。
Counterexample
候选图：12 个逻辑节点变成 20 个实例，总面积 20。
Fix
报告实例数与总面积；比较方案时同时看延迟与代价。

把“延迟最优”推广到禁止复制的情况

Wrong result
认为 RW 的最优性在不允许复制时依然成立。
Why
最优性证明依赖于允许复制；禁止复制后问题不同，结论不再适用。
Counterexample
候选图上禁止复制、容量 4 时，穷举得到的最好最大延迟是 10，而允许复制的 RW 结果是 8。
Fix
说明前提：DAG、节点延迟模型、固定 D、容量、允许复制。

把 RW 的“标签”当成 LP 的标签

Wrong result
以为 l(v) 是 v 所属的群体。
Why
RW 的标签是一个数：从输入到 v 的最小可能到达时间（在模型内）；LP 的标签是群体记号。
Counterexample
候选图 l(i) = 7、l(k) = 8，都是时间。
Fix
称为“延迟标签 l(v)”，与 Module 05 区分。

Scope and limits

  • 最优性来自论文（Rajaraman 与 Wong，IEEE TCAD 1995；会议版 DAC 1993），只在其模型内成立：组合 DAG、节点延迟、簇内 0、跨簇固定 D、容量约束、允许复制。本课程的测试不证明最优性，只检查实例图合法、到达时间计算一致。
  • 12 节点例子是候选复原：原作影片的图与 Δ 表复原出 15 条边，在“lv 降序、相等时逆拓扑序”的平票假设下重现 8 簇、20 实例、输出 8。原始边表与平票规则尚待原作者确认，不是教师确认的数据。
  • 课程对应待确认：教师目录的 Lab 09 是 Multilevel，本模块不替代它。
  • 本课程实现假设单位大小时逐个加入候选（前缀），一般大小下的装入策略与论文细节需进一步核对。
  • 复制带来面积代价；实际设计还要考虑引脚、功耗等，本章不讨论。
