01 / Goals and problem

What this module solves

Start with the problem and what counts as success, then the algorithm. Each goal links to where it is taught.

RecapThe first three modules really put members together by merging. This module merges no nodes at all: each node only updates the label it carries, and a group is “the nodes with the same label”.

Learning goals

  1. Tell a node’s name (identity, fixed) from its label (membership, changing), and explain why the algorithm needs no K.Why connections form groups · Names, labels and membership · [Concept] Names and labels
  2. Count weighted votes by label: C’s votes are B = 1 + 4 = 5, D = 2, E = 1. Weight is compared, not the number of neighbours.One update: a weighted vote by label · [Trace] C’s votes

  4. Tell apart the three stopping states stable, cycle and limit; find a cycle under synchronous updates.Synchronous updates, cycles, ties and edge weights · [Explore] Find a cycle
  5. Explain how visiting order, tie rule and edge weights change the result and the round count (reverse order: 3 rounds; C–D = 10: cut 5).Synchronous updates, cycles, ties and edge weights · [Explore] Strengthen one bridge

Problem statement

Input

A weighted undirected graph, a visiting order, an update mode (async / sync), a tie rule (min / max / keep), and a maximum number of rounds.

Output

Each node’s final label, the groups by label, the votes at every step, the cut, the number of rounds and the stopping state.

Objective

Let tightly connected nodes gather under one label “by themselves”, without fixing the number of clusters in advance.

Constraints

Each update reads only that node’s neighbours; node names never change; the tie rule must be deterministic.

Assumptions

Edge weights are positive and mean connection strength; each node starts with its own name as its label; an isolated node keeps its label.

Stopping

stable: a full round with zero changes; cycle: a label state repeats; limit: the maximum number of rounds is reached. Only stable may be called “converged”.

§ 1Why connections form groups

Picture an address book: a few hundred names to sort into circles. You don't need to know who anyone is. You only need to see who keeps in touch with whom: ties are dense inside a circle and sparse between circles. Network science calls this community detection.

In 2007, Raghavan, Albert and Kumara proposed a minimal method: everyone looks at which circle their friends belong to right now and joins the one they are most connected to; repeat, and the circles emerge on their own. On the fictional address book from Su3037's original film (28 people, 61 ties) it stops after 3 rounds with three circles of 8 + 10 + 10, cutting a total weight of only 4.

A chip has the same problem: wires inside a block are short, wires between blocks have to be long. Carry the local rule "look at your neighbours, follow the strongest" over to the chip and you have label propagation.

The analogy only explains structure

The address book only builds intuition: nodes, edges and weights have the same structure. It says nothing about which circle real people "should" belong to and infers no causes. Edge weights between chip cells in this course are invented teaching values.

§ 2Names, labels and membership

node name

节点名

The node's identity; it never changes. The nodes of G01 are always A, B, C, D, E.

label

标签

The group marker a node currently carries; it gets updated. At the start every node's label is its own name.

grouping

分组

Nodes with the same label form a group. Compare two results by their groups, not by what the labels are called.

A name is identity; a label is membership. "C's label becomes B" does not mean "C is renamed B".

Unlike the previous three modules, there is no merging at all here, and no K is given: how many groups there are at the end is up to the labels.

§ 3One update: a weighted vote by label

When node v takes its turn, group its neighbours by their current label, add up the edge weights within each label, and take the label with the largest total:

new label(v) = argmax_L Σ w(u, v), summed over the neighbours u of v whose label is L.

C by hand (round 1): updating asynchronously in the order A→E, by the time C is visited A has already switched to label B, and B is still B. C's neighbours and votes:

LabelFromVotes
BA (1) + B (4)5
DD (2)2
EE (1)1

C's new label is B, and its name is still C. What counts is weight: if two neighbours B and C carry label B with edge weight 1 each, and one neighbour D carries label D with weight 4, then B = 2 and D = 4, and D wins. More neighbours do not necessarily win.

Ties need a fixed rule. This course implements three: min takes the alphabetically smallest candidate (the default), max takes the largest, and keep keeps the current label if it is among the tied ones. An isolated node with no neighbours keeps its own label.

§ 4A full round, visiting order, and when to stop

Round 1 (asynchronous: each update is written back at once, so later nodes see it immediately):

VisitVotes seenNew labelChanged
AB 5, C 1Byes
BB 5, C 4Bno
CB 1+4=5, D 2, E 1Byes
DB 2, E 5Eyes
EB 1, E 5Eno

End of round 1: B B B E E, with 3 nodes changed.

Round 2: check all 5 nodes again; none changes, and only now is the result confirmed stable. So the number of rounds is 2, and the cut is C–D 2 + C–E 1 = 3.

Why one more round

In round 1, B and E did not change, but nodes after them were still changing; as long as any node changes, the earlier nodes may see different neighbours next time. Only a full round with zero changes confirms that no node still wants to change. The round count includes this confirmation round.

A different visiting order: updating in the order E→A ends with A/A/A/D/D. The label names differ, the grouping is still ABC | DE, but it takes 3 rounds. Visiting order affects the number of rounds, and on other graphs it can affect the grouping too.

§ 5Synchronous updates, cycles, ties and edge weights

asynchronous update

异步更新

Each node's result is written back as soon as it is computed; the course default.

synchronous update

同步更新

Every node in a round reads the same "old snapshot"; all results are committed together at the end of the round.

cycle

振荡

The label state returns to one seen before and repeats from then on.

Two nodes, synchronous: one edge between A and B. Synchronously, A reads B's old label B and B reads A's old label A, and both are committed at the end of the round, so they swap; next round they swap back. The state repeats, and the run reports cycle. Asynchronously on the same graph: A switches to B first, B then already sees B, and one round settles it.

G01 does this too: under synchronous updates it is B/A/B/E/D after round 1 and back to A/B/A/D/E after round 2… round 3 brings back the state of round 1. The period is 2 and the cut stays at 17.

The three stopping states must be kept apart:

StateTestCan it be called "converged"?
stablea full round with zero changesyes
cyclethe label state repeatsno
limitthe maximum number of rounds is reachedno

What edge weights do: change the weight of C–D from 2 to 10 and run again (starting over from the initial labels). D pulls C across, the result becomes AB | CDE, and the cut becomes A–C 1 + B–C 4 = 5.

§ 6Reading the pseudocode line by line

  1. labels[v] ← v for every node
  2. repeat for round = 1, 2, …, maxRounds:
  3. snapshot ← labels (synchronous mode only)
  4. for v in order:
  5. votes ← sum edge weights by neighbour label
  6. new ← label with most votes (ties: min/max/keep)
  7. async: write back now; sync: note it down
  8. sync: commit everything at the end of the round
  9. if no change this round: stable, stop
  10. if this state was seen before: cycle, stop

Click any line for its explanation. When you step through the lab, the line being executed lights up.

How it maps to Python: line 5 → count_votes(); line 6 → choose(); lines 9–10 → the stopping test in the exercise.

§ 7Is the grouping good? Cut and limits

Once label propagation stops, judge it by the cut: ABC | DE on G01 cuts only C–D and C–E, a cut of 3.

The 24-cell fictional circuit from the author's original film makes it clearer: total edge weight is 202; cutting it into three columns by position with a "ruler" cuts 88; after 5 rounds of label propagation only 2 is cut. Trying every split of 24 cells is not realistic either: there are 1,577,585,295 ways to split them into three equal groups.

The limits need saying too:

  • No K is given and balance is not guaranteed: it may put almost every node into one group.
  • The result depends on the visiting order, the update mode and the tie rule.
  • Synchronous updates can cycle; this course does not claim that asynchronous updates stop on every graph.
  • In EDA it works well as a fast first grouping, handed on to constrained partitioning or improvement methods (Modules 06–08).

08 / Common mistakes and limits

Where it goes wrong

Each entry gives the wrong result, the cause, a counterexample and the fix; every number in the counterexamples is recomputed by the tests.

Treating the label as the name

Wrong result
Saying “C became B”.
Why
A node’s name is its identity and never changes; what changes is the label C carries.
Counterexample
After round 1, C carries label B, but it is still node C, with the same edges and weights.
Fix
Say “C’s label becomes B”, and read groups as “nodes with the same label”.

Counting neighbours instead of weight

Wrong result
A has two neighbours with B and one with D, so B wins.
Why
A label’s votes are the sum of edge weights of the neighbours carrying it, not their number.
Counterexample
The tie graph from the original Lab05 repository: B and C carry B (1 each), D carries D (4). Weighted, B = 2 and D = 4, so A picks D.
Fix
Add up edge weights per label.

Calling it converged because some nodes did not change

Wrong result
B and E did not change in round 1, so they are stable.
Why
Once a later node changes, earlier nodes see different neighbour labels next time.
Counterexample
Three nodes change in round 1 on G01; only a full round 2 with zero changes confirms stable, for 2 rounds in total.
Fix
Use “a full round with zero changes” as the test for stable, and count that confirmation round.

Calling a cycle “unfinished” or “converged”

Wrong result
Synchronous updates still change at the round limit, so report stable or raise the limit.
Why
Synchronous updates read one old snapshot, so two nodes that support each other swap labels at the same time and keep returning to the same state.
Counterexample
Two nodes, synchronous: A↔B swap back and forth; G01 under synchronous updates also returns to round 1’s state in round 3 (period 2).
Fix
Detect repeated states and report cycle; compare against asynchronous updates or another tie rule.

Comparing results by label names

Wrong result
Forward order gives B/B/B/E/E and reverse order gives A/A/A/D/D, so the results differ.
Why
Label names are only markers; a grouping is about who is together.
Counterexample
Both are ABC | DE.
Fix
Compare normalised groupings, not label strings.

Scope and limits

  • No K is given and group sizes are not balanced: one large group may swallow almost every node.
  • The result depends on visiting order, update mode and tie rule; on the same graph, a different rule can change the number of rounds and even whether it stops.
  • Synchronous updates can cycle; asynchronous updates stop on these examples, but the course does not claim they stop on every graph.
  • The original paper (Raghavan, Albert, Kumara, 2007) stresses near-linear time: each round reads every edge a constant number of times. This course’s implementation follows that idea, scanning each node’s neighbours in turn.
  • The 24-cell circuit and the contact graph are fictional teaching graphs; their numbers describe only those graphs.
